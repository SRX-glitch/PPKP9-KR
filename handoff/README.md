# PPKP9 한글패치 — 시나리오 번역 인수인계 패키지

파워프로군 포켓9(NDS) 「사스라이의 나이스가이」 시나리오 번역을 이어받기 위한 자료 일체.
**ROM·에뮬레이터·원본 저장소 없이 이 폴더만으로 작업할 수 있다.** 필요한 건 Python 3.8+와 텍스트 편집기(또는 스프레드시트)뿐이다.

현재 진행률: **28,169개 대사 중 16,539개(58.7%) 완료.** 이 폴더의 목록을 다 채우면 **약 82%**가 된다(나머지는 순수 문장부호·효과음 등 번역이 불필요하거나 불가능한 줄).

> **필요한 것:** Python 3.8 이상, 텍스트 편집기(또는 스프레드시트). 그게 전부다.
> 폴더는 아무 데나 두어도 되고 이름을 바꿔도 된다. 모든 파일은 UTF-8이다.

## 1. 5분 안에 시작하기

`work/shard_001.tsv` ~ `shard_135.tsv`(각 50줄)가 이미 들어 있다. 다시 만들려면:

```bash
python make_shard.py            # 50줄 단위 (기존 파일은 건드리지 않는다)
```

> ⚠ **shard 하나 = AI 요청 하나.** 50줄은 품질이 유지되는 상한이다.
> 1차 제출은 150줄짜리를 한 번의 요청에 통째로 넣었다가 **전량 반려**됐다 —
> 앞부분은 정확했지만 뒤로 갈수록 원문과 무관한 번역이 나왔다. 자세한 내용은 `QA_REPORT.md`.

`ko` 열을 채운 뒤:

```bash
python validate.py work/shard_001.tsv
```

`OK - no errors.` 가 나오면 그 파일을 그대로 돌려주면 된다.

**작업 순서는 `shard_001`부터.** 목록이 게임 내 등장 횟수 순으로 정렬돼 있어서, 앞쪽 파일일수록 플레이어가 자주 보는 텍스트다. 중간에 그만두어도 눈에 띄는 부분부터 채워진 상태가 된다.

## 3. 작업 파일 형식

| 열 | 의미 |
|---|---|
| `id` | 줄 식별자. **절대 수정 금지** |
| `occ` | 게임에서 이 대사가 나오는 횟수 |
| `max` | **한국어 최대 글자 수. 공백 포함.** 넘으면 대사 상자가 밀린다 |
| `prev` | 스크립트에서 **바로 앞** 대사 — 문맥용, 번역 대상 아님 |
| `jp` | 번역할 일본어 원문. **절대 수정 금지** |
| `next` | 스크립트에서 **바로 뒤** 대사 — 문맥용, 번역 대상 아님 |
| `ko` | **여기만 채운다** |

> **`jp`를 수정하면 그 줄은 게임에 들어가지 못한다.** `id`와 `jp`의 짝이 원본 스크립트 위치를 찾는 유일한 열쇠이기 때문이다. `validate.py`가 수정 여부를 검사한다.

> **비워 두어도 된다.** 판단이 안 서는 줄은 공백으로 남긴다. 억지 번역보다 낫고, 다음 사람이 이어받는다.

### 스프레드시트로 작업할 때
TSV(탭 구분, UTF-8)다. 엑셀/구글 시트에서 열 때 **구분자를 탭으로, 인코딩을 UTF-8로** 지정하고, 저장도 반드시 **탭 구분 UTF-8**로 한다. 
⚠ 엑셀은 앞자리 `0`이나 `~`로 시작하는 셀을 멋대로 바꾸는 일이 있으니, 저장 후 `validate.py`를 꼭 다시 돌린다.

## 4. `validate.py`가 잡아 주는 것

- `max` 글자 수 초과 (공백 포함해서 셈)
- 게임 폰트에 없는 문자 — 반각 `( ) ~ % ! ?` 등. **대체할 전각 문자를 알려 준다**
- 한글 자모 단독 사용 (`ㅂ` 등 — 폰트에 완성형만 있다)
- 수정된 `jp`, 존재하지 않는 `id`, 여러 파일에 중복된 `id`
- 번역 결과가 원문과 동일한 경우 (경고)

마지막에 이번 제출이 채운 줄 수와 **게임 내 등장 횟수 합계**가 출력된다. 등장 횟수가 실제 체감 진행률이다.

### `WARN`은 무시하지 말 것
`ERROR`와 달리 제출을 막지는 않지만, **1차 반려의 핵심 증상이 이 두 가지였다.**

- `is far shorter than the source` — 원문 대비 3분의 1 이하. 문장 일부만 옮겼거나 다른 줄 내용일 가능성.
- `is used for N different source lines` — 같은 번역문이 서로 다른 원문에 붙었다. 한 문장을 여러 조각에 나눠 붙인 흔적.

검증된 기존 번역 1,157줄에 이 규칙을 적용하면 **경고가 하나도 나오지 않는다.**
반면 반려된 1차 제출에서는 806줄 + 중복 242종이 걸렸다. 즉 경고가 뜨면 대개 진짜 문제다.

> ⚠ **검사기는 "내용이 맞는지"를 판정할 수 없다.** 문법에 맞는 한국어면 통과한다.
> 실제로 반려된 shard 중에도 `ERROR` 0건으로 통과하는 파일이 있었다.
> **묶음마다 무작위 5줄을 골라 `jp`와 `ko`를 직접 대조하는 것이 유일한 방어선이다.**

## 5. 돌려주는 방법

`ko`를 채운 `work/*.tsv` 파일을 **그대로** 보내면 된다. 형식 변환·이름 변경 불필요.
받는 쪽에서 `tools/merge_handoff.py`로 병합해 ROM을 다시 빌드한다.

> ⚠ **`id`와 `ko`만 뽑아 새 파일을 만들지 말 것.** AI가 `id<TAB>ko`로 답하더라도, 그 결과는
> **원래 shard 파일의 `ko` 열에 채워 넣어야** 한다. `jp` 열이 "이 id가 정말 이 원문을 가리키는가"를
> 증명하는 유일한 대조 수단이라, 없으면 검사기와 병합 도구 모두 파일을 거부한다.

**부분 제출 환영.** 150줄 중 40줄만 채워도 그대로 반영된다. 완성될 때까지 붙들고 있지 않아도 된다.

## 6. 자주 나오는 질문

**Q. 문장이 중간에서 잘려 있는데요?**
정상이다. 원본 스크립트가 이름 삽입·줄바꿈 제어 코드에서 분할돼 있어서 이런 줄이 아주 많다. `prev`/`next`를 읽고 **조각인 채로** 번역한다. `POLICY.md` 4장에 자세히 나와 있다.

**Q. 앞에 `い`나 `え` 같은 가나가 하나 붙어 있어요.**
선택지 번호 표시다. **그 가나는 남기고 뒤만 번역한다.** `い読む` → `い읽는다`

**Q. 이름 뒤에 붙는 조사는 받침을 어떻게 처리하나요?**
플레이어가 이름을 직접 입력하므로 받침을 알 수 없다. `가/는/를/에게` 한 형태만 쓴다. `이(가)` 병기는 자리만 차지하므로 쓰지 않는다.

**Q. 번역 품질은 어느 정도여야 하나요?**
이 패치는 1차 기계번역 수준을 허용한다는 전제로 진행돼 왔다. 완벽함보다 **진도와 일관성**이 우선이다. 다만 캐릭터 말버릇(`~다 게`, `~습죠` 등)은 개성이므로 반드시 살린다.

**Q. 한글 음절 수 제한이 있다고요?**
게임 폰트에 한글 슬롯이 1,658칸 있고 현재 1,107칸을 썼다. 남은 목록을 전부 번역해도 1,214칸 정도로 예상되므로 **실질적으로 신경 쓸 필요 없다.** 특이한 음절을 일부러 피할 이유는 없다.
