# PPKP9 한글화 번역 방침

파워프로군 포켓9(NDS) 「사스라이의 나이스가이」 시나리오 번역 규칙.
**이 문서는 그대로 AI 프롬프트에 붙여넣어도 되도록 쓰여 있다.**
2026-07-26까지 12,747줄을 번역하며 확정된 내용이고, 판정 근거는 `data/reference_translations.tsv`에 실물로 남아 있다.

---

## 0. 가장 중요한 3가지

1. **`jp` 열은 절대 수정하지 않는다.** `id`와 `jp`의 짝이 원본 스크립트를 찾는 유일한 열쇠다. 한 글자만 바뀌어도 그 줄은 게임에 들어가지 못하고 조용히 사라진다. `ko` 열만 채운다.
2. **`max` 열의 글자 수를 넘지 않는다.** 공백도 1글자로 센다. 넘으면 대사 상자가 한 줄 더 밀려서 문장이 잘린 것처럼 보인다.
3. **못 하겠으면 비워 둔다.** 빈 칸은 정상이고 다음 사람이 이어받는다. 억지로 지어내는 것보다 훨씬 낫다.

---

## 1. 글자 수 (`max` 열)

한 줄은 전각 19글자다. 원문이 두 줄짜리면 `max`가 38로 나온다.

- **공백도 1글자.** 「그래서 이렇게 한꺼번에 사 두지」는 15자가 아니라 19자다.
- 넘칠 때는 **의미를 버리지 말고 표현을 줄인다**: 「하지만」→「근데」, 「그러니까」→「그러니」, 「~하지만」→「~지만」, 「자기」→「제」, 「나는」→「난」, 「너를」→「널」.
- 그래도 안 되면 **문장 끝을 원문처럼 잘라도 된다.** 원문 자체가 다음 줄로 이어지는 조각인 경우가 많다(아래 4번).

## 2. 문장부호 — 전각만 쓴다

| 쓸 것 | 쓰면 안 되는 것 |
|---|---|
| `。` `、` `！` `？` | `.` `,` `!` `?` |
| `（` `）` | `(` `)` |
| `～` | `~` `—` |
| `「` `」` | `"` `'` |
| `・` `…` | `·` |

**게임에 글리프가 없는 문자를 쓰면 그 줄은 통째로 버려진다** — `(` `)` `~` `%` `—` `"` `'` 가 여기 해당하고, `validate.py`가 에러로 잡는다.

⚠ 반각 `!` `?` `.` `,` 는 게임에 글리프가 **있어서** `validate.py`가 통과시킨다. 하지만 폭이 한글의 2/3라 섞이면 어색하고, 기존 12,747줄이 전부 전각을 쓴다. **일관성을 위해 전각으로 쓴다** — 검사기가 막지 않는 규칙이므로 직접 지켜야 한다.

- 말줄임표는 **원문의 `・` 개수를 그대로 따라간다.** 「・・・」는 「・・・」로. 길이가 모자라면 개수를 줄여도 된다.
- **한글 자모 단독(ㅂ, ㅅ, ㄴ…)은 금지.** 폰트에 완성형 음절만 있다. 「~ㅂ죠」가 아니라 「습죠」.
- 숫자·알파벳은 전각(`１２３`, `ＡＢＣ`)과 반각(`123`, `ABC`) 둘 다 있다. **원문이 쓴 쪽을 그대로 따른다.**

## 3. 말투와 호칭 (확정, 바꾸지 말 것)

### 캐릭터 말버릇 — 개성이므로 반드시 살린다
| 원문 | 한국어 | 예 |
|---|---|---|
| `でやんす` (개 캐릭터) | `~습죠 / ~입죠` | 「모르는 사람과는 말 안 합죠。」 |
| `カニ` (게 캐릭터) | 어미 `~다 게` | 「사전답사하러 왔다 게！」 |
| `ムシャ` | `우걱` | 「인사하러 왔을 뿐이야 우걱。」 |
| `ボ～ク` (1인칭) | `나～ / 내～` (전각 `～` 유지) | 「나～ 힘낼게！」 |
| `にゃ` (고양이) | `~냥` | 「노리는 놈인 거냥？」 |
| `でござる` (사무라이) | `~소 / ~오`체 | 「실성하셨소！」 |
| `であります` (군인풍) | `~입니다` 정중체 | 「순찰로 돌아가겠습니다！」 |

### 호칭
| 원문 | 한국어 |
|---|---|
| `さん` | `씨` |
| `ちゃん` | `짱` (准ちゃん→준짱) |
| `くん` | `군` |
| `お嬢様` | `아가씨` |
| `ご主人様` | `주인님` |
| `おじちゃん` `母ちゃん` 등 가족 호칭 | `아저씨` `엄마` — 의미로 번역 (짱 아님) |

### 고유명사 — 인물과 지명의 규칙이 다르다
- **인물 이름 = 일본어 음** : 維織→이오리, 三浦→미우라, 寺門→지몬, 城田→시로타, カンタ→칸타
- **지명·시설·기술명 = 한자음** : 少森寺→소삼사, 遠前町→원전정, 遠前支店→원전 지점, 木川古書店→목천 고서점, 電視炎斬→전시염참
- 팀·단체명은 음차 : ニコニココアラーズ→니코니코 코알라즈, 狂犬ドッグス→광견 독스

### 기타 확정
- 운세 등급 = **길 / 대길 / 말길 / 흉 / 대흉** (한자 병기 없음)
- `％`는 「할」로 (2割 → 2할)

번역 중 이 목록에 있는 단어를 만나면 **그대로 따른다.** 새로 지어내면 같은 가게·같은 팀이
화면마다 다른 이름으로 나온다.

주요 확정분: 商店街=상점가 · 野球=야구 · 試合=시합 · チーム=팀 · コーヒー=커피 · バイト=알바 ·
メイド=메이드 · 劇団=극단 · 会長=회장님 · ご主人様=주인님 · キャプテン=주장 · 芝居=연극 ·
カレー=카레 · カード=카드 · イベント=이벤트 · 大丈夫=괜찮아

### 문맥에 따라 갈리는 것 (통일하지 말 것)
같은 단어라도 아래는 **의미가 다르므로 갈라 쓰는 게 맞다.** 억지로 하나로 통일하지 않는다.

| 원문 | 갈래 |
|---|---|
| `絶対` | 부정문이면 **절대**(절대 안 해)、긍정·의지면 **반드시**(반드시 이긴다) |
| `ボール` | 일반 대화는 **공**、야구 용어 조합은 **볼**(볼카운트·스트라이크와 볼) |
| `子供` | 아이 일반은 **아이/애**、`子供の頃`처럼 시절을 가리키면 **어릴 적** |
| `人間` | 종·개념이면 **인간**、그냥 사람을 가리키면 **사람** |
| `自分` | 주어면 **자기/자신**、`自分で`는 **직접/스스로** |

### 1인칭 (음차 금지)
`オイラ`·`ボク`·`オレ`·`ワシ` 는 **전부 나/내/우리**로 옮긴다. `오이라`처럼 음차하지 않는다.
단 `ボ～ク`의 늘임(`～`)은 말버릇이므로 `나～`로 살린다.

## 4. 조각난 줄을 만났을 때 — 이게 이 프로젝트에서 제일 헷갈리는 부분

원문 스크립트는 **이름 삽입·줄바꿈 제어 코드에서 잘려 있다.** 그래서 목록에는 문장 중간부터 시작하거나 중간에서 끝나는 줄이 아주 많다. `prev` / `next` 열에 **앞뒤 줄**이 들어 있으니 반드시 같이 읽는다.

- **조각은 조각인 채로 번역한다.** 앞에 이름이 들어갈 자리라면 그 앞은 비어 있는 게 정상이다.
  - `さんは、どこに行きたいんだ？` → `씨는 어디 가고 싶어？` (게임에서는 「칸타씨는 어디 가고 싶어?」로 보인다)
  - `が仲間になった！）` → `가 동료가 되었다！）`
  - 일본어와 한국어는 어순이 같아서 이 방식이 대체로 자연스럽게 맞아떨어진다.
- **조사는 받침을 모르는 상태로 붙는다.** 이름이 뭐가 들어올지 알 수 없으므로 `가/는/를/에게`처럼 **모음 받침 기준 하나만** 쓴다. `이(가)` 같은 병기는 자리를 낭비하니 쓰지 않는다.
- **앞에 홑가나(い / う / え / き / く …)가 붙은 줄은 선택지 번호 표시다.** 잘린 게 아니다. **가나를 그대로 남기고 뒤만 번역한다.**
  - `い読む` → `い읽는다`, `え打撃について` → `え타격에 대해서`
- **문장 끝이 어중간해도 그대로 둔다.** `~していないん` 같은 꼬리는 다음 줄로 이어진다.

## 5. 번역하지 말아야 할 것 (비워 두고 넘어간다)

- **디버그 메뉴** : `三浦のシナリオテスト` 다음에 오는 `く映画館ＳＰ` `く城田連続１` 류
- **의미 없는 문자열** : `（あいうえおいうえおあうえお` 같은 테스트 더미
- **무엇을 가리키는지 앞뒤로도 판단이 안 되는 조각** — 억지 번역보다 공백이 낫다
- 한국어와 똑같아지는 순수 문장부호 줄 (`・・・・・・。`) — 애초에 목록에 없다

## 6. 번역 톤

- **캐주얼한 구어체.** 이 게임은 야구 육성 시뮬레이션의 코미디 시나리오다. 문어체 번역투를 피한다.
- **반말/존댓말은 화자 관계를 따른다.** `prev`/`next`로 누가 누구에게 말하는지 유추한다. 애매하면 원문의 정중도(`~です/ます` vs 반말)를 그대로 따른다.
- **오역보다 어색함이 낫고, 어색함보다 공백이 낫다.** 이 패치는 1차 기계번역 수준을 허용한다는 전제로 시작했다. 완벽을 노리다 진도가 안 나가는 쪽이 더 나쁘다.
- **일관성 > 개별 문장의 완성도.** 같은 표현이 이미 번역돼 있으면 `data/reference_translations.tsv`와 `data/glossary_auto.tsv`를 검색해 그쪽에 맞춘다.

## 7. AI에게 시킬 때 주의할 점

- **반드시 `prev`/`next`를 함께 준다.** 조각난 줄이 많아서 문맥 없이는 AI가 문장을 지어낸다.
- **`max` 글자 수를 프롬프트에 넣고, 받은 뒤 `validate.py`로 다시 센다.** 모델은 글자 수를 자주 틀린다.
- **`jp`를 다시 출력시키지 않는다.** `id`와 `ko`만 받는다. 원문을 재생성시키면 미묘하게 바뀌어서 매칭에 실패한다.
- **한 번에 30~50줄** 정도가 품질이 안정적이다. 200줄씩 던지면 뒤로 갈수록 방침을 잊는다.
- 용어집과 이 문서를 매 요청마다 다시 붙인다. 대화가 길어지면 초반 지시를 잃는다.

## ⚠ 선행 카나 마커 — 세션27 정정

세션25 메모는 "줄 앞의 카나 1자(い/う/え/き/く…)는 **메뉴 인덱스 마커**이니 한국어에도 그대로 남겨라"고 했다.
그 표기 규칙 자체는 유지한다(`い読む` → `い읽는다`).

**다만 "마커를 보존하면 안전하다"는 보장은 없다.** 세션27에서 선택지 화면이 비어 그려지는 회귀가 나왔고,
마커가 붙은 런만 되돌려도 재현됐다 — 즉 마커는 원인이 아니었고, 원인은 아직 미상이다.

실무 규칙:
1. 마커는 **반드시 원문 그대로** 남긴다(번역·삭제·치환 금지).
2. 마커가 붙은 런을 새로 번역했다면, **그 빌드는 선택지 화면을 반드시 눈으로 확인**한다(RESUME 3장의 오라클).
3. `tl.py`의 `_skippable`이 `のの`/`はは` 같은 **이중 카나 마커를 ✗로 표시**한다. 표시된 줄은 비워 두는 게 기본이다.
