## 2. 기계 검사로 잡히지 않는 결함 — 이쪽이 본질적 문제

`ko`가 문법에 맞는 한국어이고 글자 수도 지켜서 검사기가 통과시키지만, **그 행의 원문과 내용이 다르다.**

| 원문 | 제출된 번역 | 실제 뜻 |
|---|---|---|
| `宙空不動産` | `완료했습니다。` | 부동산 상호 |
| `とりあえず、お茶でもいれるわ。` | `아저씨！` | 일단 차라도 끓일게 |
| `お互い協力すれば、` | `빅토리즈` | 서로 협력하면 |
| `もう準備してあるでやんす。` | `좋아、해볼까！` | 이미 준비돼 있습죠 |
| `いつもは無駄遣いしないんだけど` | `눈물이 안 나면 눈이 건조해지고。` | 평소엔 낭비 안 하는데 |
| `ところで、今日はどうしたんだ？` | `보물을 찾으러 왔습죠。` | 그런데 오늘은 무슨 일이야？ |

**같은 번역문이 서로 다른 242종·557줄에 중복 사용됐다.** 예: `완료했습니다。`가 `宙空不動産`·`落下点表示`·`凡田博物館` 등 24개 행에 붙어 있다.

⚠ 행 정렬 자체는 어긋나지 않았다(오프셋 ±3 검사에서 현재 정렬이 최적). 즉 **밀어서 복구할 수 없고, 내용을 다시 만들어야 한다.**

## 3. 품질이 shard 순서대로 무너진다

각 shard에서 무작위 표본을 직접 읽어 확인한 정확도다. 표본이 shard당 7~14줄로 작아 정밀한 수치는 아니지만 경향은 분명하다.

| shard | 표본 정확도 | 판정 |
|---|---|---|
| 001 | 13/14 | 사용 가능 |
| 002 | 6/7 | 사용 가능 |
| 003 | 5/7 | 경계 |
| 004 | 3/7 | 불가 |
| 005 | 4/7 | 불가 |
| 008 이후 | 0~1/5 | 불가 |

**원인은 `POLICY.md` 7장이 경고한 그대로다** — 150줄짜리 shard를 통째로 한 번의 요청에 넣으면 뒤로 갈수록 방침과 원문 대응을 잃는다. 문서에 적힌 권장 단위는 **한 번에 30~50줄**이다.

## 5. 재작업 요청 사항

1. **한 번에 30~50줄**로 나눠 요청한다. shard 파일을 통째로 프롬프트에 넣지 않는다.
2. **매 요청마다 `POLICY.md`와 용어집을 다시 붙인다.** 대화가 길어지면 초반 지시를 잃는다.
3. **결과를 받으면 `id`가 정확히 대응하는지 눈으로 확인한다.** 이번 제출의 가장 큰 문제는 문장력이 아니라 행 대응이다.
4. `validate.py`를 갱신본으로 교체했다 — 원문을 그대로 둔 줄과 한자 혼용을 이제 에러로 잡는다. 제출 전 반드시 통과시킨다.
5. 말버릇·호칭은 `POLICY.md` 3장 표를 그대로 따른다.

## 6. 참고: 검사기가 왜 통과시켰나

게임 폰트에는 원래 일본어 글리프가 들어 있어서 **모든 한자·가나가 유효한 문자**다. 따라서 원문을 그대로 `ko`에 둬도 "글리프 없음" 검사에 걸리지 않았다. 이번에 "한글이 하나도 없으면 에러" 규칙을 추가해 막았다.

다만 **내용이 맞는지는 기계가 판정할 수 없다.** 2장 유형은 앞으로도 사람이 확인해야 한다.
