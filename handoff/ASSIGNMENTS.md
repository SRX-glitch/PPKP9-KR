# 작업 분담 대장

누가 어느 shard를 들고 있는지 적는 곳. **shard를 꺼내기 전에 여기부터 본다.**

전체 **135개 shard / 6,707줄** (shard당 50줄, 마지막만 7줄).

두 사람이 같은 shard를 번역하면 `merge_handoff.py`가 중복으로 거르긴 하지만,
그때는 이미 한쪽의 번역 노동이 통째로 버려진 뒤다. 겹치지 않게 나누는 게 전부다.

## 규칙
- **가져갈 때** 아래 표에 줄을 추가한다. 가져가지 않은 shard는 적지 않는다(135줄짜리 표는 관리가 안 된다).
- **돌려줄 때** 상태를 `제출`로 바꾼다. 병합이 끝나면 관리자가 `반영`으로 바꾼다.
- 중간에 그만두면 그 줄을 지운다. 부분 번역은 그대로 제출해도 된다.
- **한 사람이 5개 이상 동시에 잡지 않는다.**
- ⚠ **shard 하나 = AI 요청 하나.** 여러 shard를 한 번에 프롬프트에 넣지 않는다(아래 이력 참고).

## 진행 중 / 완료

| shard | 담당 | 상태 | 가져간 날 | 제출한 날 | 비고 |
|---|---|---|---|---|---|
| shard_001 ~ 004 | 관리자(직접) | **반영** | 2026-07-27 | 2026-07-27 | 197줄, batch119로 병합·빌드·콜드부팅 확인 |

⚠ **외부 위탁은 2회 연속 반려 후 중단.** shard_005부터가 다음 작업 구간이다.

## 이력

### 2026-07-27 — shard_001~004를 관리자가 직접 번역해 반영 (batch119)
- 197줄 등록(3줄은 디버그 메뉴·더미라 의도적 공백). 커버리지 58.71% → 59.41%.
- 같은 QA 기준을 자기 작업에도 적용한 결과 **검사기 쪽 오탐 3건**을 발견해 수정
  (`・`/`ー` 오판, 마커 화이트리스트, `お`·`おばあちゃん` 필터). 자세한 내용은 RESUME.md.

### 2026-07-27 — 2차 제출도 전량 반려
- 135개 shard(50줄 단위) / 6,041줄 제출 → **반영 안 함.** `_rejected_r2_20260727/`에 보관.
- **재작업이 실제로 이루어지지 않았다**: 6,041줄 중 4,095줄(68%)이 1차와 바이트 동일,
  1차 보고서에 인용한 줄들도 그대로, 135개 파일 수정 시각 동일.
- 1차 ERROR 634줄의 처리: 한국어 번역 66줄(10%) / **한자를 지워 문장부호만 남김 297줄(47%)** / 공백 271줄.
  `ういい人だな。` → `人。` → `。` — 검사 규칙이 "한자+한글없음"이라 **한자를 지우면 통과**했다.
- 조치: 규칙을 "한글이 하나도 없으면 무조건 에러"로 변경 → 1,597줄(26.4%) 검출.
- 한글이 있는 4,444줄도 표본 20줄 중 14줄 오류.
- ⚠ **관리자는 제출물을 받는 즉시 `_rejected_*`처럼 사본을 남길 것.** 2차 검수 때
  1차 사본만 있어 "정말 재작업됐는지"를 바이트 비교로 확인하는 데 우회가 필요했다.

### 2026-07-27 — 1차 제출 전량 반려
- 45개 shard(150줄 단위) / 6,389줄 제출 → **반영 안 함.** `_rejected_20260727/`에 보관.
- 사유: 상당수의 `ko`가 같은 행의 `jp`와 무관한 내용. 무작위 표본 24줄 중 16줄이 오류.
  같은 번역문이 242종·557줄에 중복 사용(`완료했습니다。`가 24개 행에 붙는 식).
- 원인: **150줄 shard를 통째로 한 번의 요청에 투입.** shard_001은 표본 13/14로 양호했으나
  뒤로 갈수록 붕괴해 008 이후는 사실상 전부 오류.
- 조치: shard 기본 크기를 **150 → 50줄**로 낮춤(`make_shard.py`). 50 초과 시 경고 출력.
  `validate.py`에 "한글이 하나도 없으면 에러", "한글에 한자 혼용 시 에러" 규칙 추가
  (기존 검사기는 원문을 그대로 둔 634줄을 통과시켰다 — 게임 폰트에 일본어 글리프가
  있어 모든 한자가 유효 문자이기 때문).
- 상세: `QA_REPORT.md`

## 관리자 메모 (ROM 빌드 담당)

- 회수: `python tools/merge_handoff.py handoff/work/shard_00X.tsv --batch <N>`
  → `translation/batch<N>.tsv` 생성. 출력된 줄을 `build_kr.main()` 로더에 추가하고 빌드.
- **병합 전 반드시 `python tools/qa_submission.py handoff/work/*.tsv` 를 돌린다.**
  `validate.py`는 기계적 적재 가능성만 본다. 내용이 원문과 맞는지는 이쪽에서 표본을 읽어야 한다.
- **`handoff/` 재생성(`tools/make_handoff.py`)은 언제 해도 안전하다.** id가 원문 해시라
  재생성해도 값이 바뀌지 않으므로, 밖에 나가 있는 shard가 무효화되지 않는다.
- **외부 작업이 진행 중이면 저장소에서 직접 번역하지 않는다.** 꼭 해야 하면
  이 표에서 뒤쪽 shard 구간을 자기 몫으로 잡아 두고 시작한다.
